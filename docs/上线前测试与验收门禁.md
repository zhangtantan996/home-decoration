# 上线前测试与验收门禁

本文档用于当前“轻预约”版本上线前验收。上线口径为：小程序获客、智能报价、预约线索、Ops 跟进、转项目、进度查看、Admin 治理；不恢复线上支付、退款、投诉、订单成交闭环。

## 1. 推荐执行顺序

| 阶段 | 命令 | 用途 |
| --- | --- | --- |
| 日常门禁 | `npm run verify:launch:standard` | 后端、Admin、Ops、小程序、轻预约 API 冒烟、`git diff --check` |
| 只跑 API 冒烟 | `npm run verify:launch:smoke` | 快速检查 API 与轻预约关键读接口 |
| 只跑安全扫描 | `npm run verify:launch:security` | 调用现有安全扫描脚本，默认跳过 DAST |
| 只跑压测 | `npm run verify:launch:perf` | 调用 k6 轻预约压测 |
| 完整上线门禁 | `npm run verify:launch` | 日常门禁 + 安全扫描 + k6 压测 |

`verify:launch` 是上线前最终门禁。当前没有测试/预发服务器时，本地环境必须承担完整构建、单测、只读压测和可控写入验证；生产环境只允许只读烟测和低强度只读探测，不能用生产写入压测补齐本地验证缺口。

## 2. 轻预约 API 冒烟

本地开发环境默认只验证安全读接口，不写入测试数据：

```bash
LIGHT_SMOKE_EXEC_CONTAINER=home_decor_api_local \
npm run verify:launch:smoke
```

生产环境只允许只读烟测：

```bash
API_BASE_URL=https://api.hezeyunchuang.com/api/v1 \
npm run verify:launch:smoke
```

可选鉴权读接口只建议使用临时低权限账号：

```bash
API_BASE_URL=https://api.hezeyunchuang.com/api/v1 \
OPS_ADMIN_TOKEN=<ops-readonly-token> \
ADMIN_TOKEN=<admin-readonly-token> \
npm run verify:launch:smoke
```

写入冒烟只允许本地开发环境：

```bash
API_BASE_URL=http://127.0.0.1:8080/api/v1 \
USER_TOKEN=<user-token> \
ENABLE_WRITE_SMOKE=1 \
SMOKE_PROVIDER_ID=<designer-or-company-id> \
SMOKE_PROVIDER_TYPE=designer \
npm run verify:launch:smoke
```

写入冒烟会创建测试报价线索、预约和反馈。脚本会阻止对 `hezeyunchuang.com` 生产域名开启 `ENABLE_WRITE_SMOKE=1`。

## 3. k6 压测

安装：

```bash
brew install k6
```

若本机未安装 `k6`，脚本会自动尝试 Docker 版 k6。打本地 Docker Compose 网络时使用：

```bash
K6_DOCKER_NETWORK=home_decoration_dev-net \
API_BASE_URL=http://api:8080/api/v1 \
npm run perf:light-appointment
```

本地只读压测：

```bash
K6_DOCKER_NETWORK=home_decoration_dev-net \
API_BASE_URL=http://api:8080/api/v1 \
K6_TARGET_VUS=50 \
K6_PEAK_VUS=100 \
npm run perf:light-appointment
```

生产低强度只读探测：

```bash
API_BASE_URL=https://api.hezeyunchuang.com/api/v1 \
K6_TARGET_VUS=10 \
K6_PEAK_VUS=20 \
K6_WARMUP_DURATION=30s \
K6_STEADY_DURATION=2m \
K6_SPIKE_DURATION=30s \
K6_COOLDOWN_DURATION=30s \
npm run perf:light-appointment
```

写入压测只允许本地开发环境：

```bash

K6_ENABLE_WRITES=1 \

npm run perf:light-appointment
```

压测结果输出到：

```text

```

## 4. 性能通过标准

| 指标 | 标准 |
| --- | --- |
| 读接口 p95 | `<= 500ms` |
| 写接口 p95 | `<= 800ms` |
| 总体 p95 | `<= 800ms` |
| 错误率 | `< 1%` |
| API CPU | 峰值 `< 70%` |
| 数据库连接 | 不打满连接池 |
| 数据库 | 无明显慢 SQL、死锁、连接泄漏 |

试运营建议本地至少跑 `50-100` VU；如果没有测试/预发服务器，不要在生产环境直接补跑写入压测或高强度峰值压测。生产只做低强度只读探测，并配合监控观察 API、数据库和网关状态。

## 5. 必测业务清单

- 小程序：首页、服务商详情、主材详情、灵感、智能报价、预约、通知、我的、进度查看。
- 预约规则：设计师、装修公司可预约；工长、主材商不可预约。
- Ops：服务商维护、主材商维护、商品维护、灵感编辑、预约跟进、报价线索跟进、转项目。
- Admin：登录、RBAC、配置中心、审计、用户治理、服务商治理、主材治理。
- 项目进度：后台/Ops 可维护项目进度；小程序只查看进度，不出现付款、退款、投诉入口。
- Feature Gate：支付、退款、投诉、线上订单新建入口关闭时必须拒绝新写入；历史数据查询不受影响。

## 6. 安全与合规门禁

- 未登录访问受保护接口返回 `401`。
- 普通用户不能访问 Admin/Ops 接口。
- Ops 用户不能越权操作系统配置、资金、权限。
- 跨用户、跨服务商、跨项目、跨主材门店 ID 访问必须被服务端拒绝。
- 上传文件必须限制类型、大小、后缀和 MIME；禁止脚本型文件作为页面执行。
- 服务商介绍、灵感内容、反馈、预约备注、通知内容要覆盖 XSS 输入测试。
- 通知 `actionUrl` 只能跳转内部允许路径。
- 手机号列表脱敏，详情按权限展示。
- API、日志、页面不得暴露 token、JWT、数据库错误、堆栈、localhost、Docker/npm 调试信息。
- 用户协议、隐私政策、个人信息清单、第三方共享清单、ICP备案号、小程序备案号预留位必须可访问。

## 7. 部署与回滚验收

- 发布脚本占位值扫描通过。
- `docker compose ... config` 通过。
- PostgreSQL 和 uploads 已备份，并记录备份路径。
- 如有 schema 变更，migration 已在生产类似旧库重复执行验证。
- HTTPS、证书、HSTS、Nginx/Gateway 路由检查通过。
- `deploy/scripts/rollback_prod.sh` 或对应测试环境回滚脚本完成演练。
- 监控告警至少覆盖 API 5xx、响应时间、数据库连接、磁盘、cron 失败、outbox dead、短信/通知失败、预约/报价提交异常下降。

## 8. Go / No-Go

满足以下条件才允许上线：

- `npm run verify:launch` 通过，或每个子门禁在等价环境逐项通过并有记录。
- 核心链路通过：小程序提交线索 -> Ops 跟进 -> 转项目 -> 小程序查看进度。
- 无未修复 P0/P1。
- 压测达到目标并保留冗余。
- migration、备份、恢复、回滚均完成演练。
- 监控告警可用。
- 已知 P2/P3 有清单、负责人和延期理由。
